## 修 /jobs 轮询自激风暴（13:00）

**现象**：`/api/v1/jobs?limit=100` 76 次/秒，后端日志 10 分钟全是同一条请求。

**根因**（`68df128` 引入，我自己的代码）：
```js
useEffect(() => {
  load()                                  // setJobs(新数组)
  const t = setInterval(...)
  return () => clearInterval(t)
}, [load, jobs])                          // jobs 在依赖里 → 自激
```
load → setJobs → jobs 变 → 副作用重跑 → 立刻再 load → …只受网络往返限制。
现象特征：频率随后端响应时间抖动（26~76/s 都出现过），因为「慢一点就慢一点地循环」。

**定位方法**（值得复用）：
1. 数日志：`wc -l` 取前后差值，算出真实 QPS，别靠肉眼
2. 按客户端端口归因：`grep -o "127.0.0.1:[0-9]*" | sort | uniq -c`，
   再用 `netstat -ano` + `Get-CimInstance Win32_Process` 把端口映射到进程
3. 隔离测量：`--headless=new --user-data-dir=/tmp/xxx` 起干净实例，只数它那个端口
4. 临时打点：在副作用里 `console.warn`，用 `--enable-logging=stderr` 抓控制台，
   直接看出"哪个副作用触发了几次、依赖值有没有变"
5. 结论：`EFFECT_LOAD 1 / 2`（StrictMode 双调用）+ 5 次 POLL_TICK = 正确；
   几十次 EFFECT_LOAD = 确认自激

**修法**：新增 `src/hooks/usePoll.ts`
- 回调存 ref，依赖只有 `[ms, enabled]` → 数据变化不可能重建定时器
- `document.visibilityState` 门控，切后台停、切回来补一次
- Tasks/Upload 加单飞守卫（在途不发第二个）+ 内容指纹（JSON 比对，没变不 setState）
- Upload 原本 1.8 秒无条件双接口 → 改成只有"有书在处理中"才轮询
- ChunkReview 处理完即停；Overview 5 秒改走 usePoll

**实测**：任务中心 15 秒 4 次；全局 ~1.5 条/秒。提交 `c250754`。

**教训**：任何 `setInterval` + `setState` 的副作用，依赖里绝不能出现被写入的那份数据；
统一走 usePoll，别在每个页面手写 setInterval。

## 修「页面内容展示不全」（13:45）

**根因**：`.app-content { display:flex; flex-direction:column; height:100%; overflow:auto }`，
而各页面都返回 **fragment**（多个平级卡片），于是每张卡都成了 flex item，
默认 `flex-shrink:1` → 内容超屏时不是滚动，而是被压缩到几像素，内容溢出被裁。

**修复**：`.app-content > * { flex: 0 0 auto }`，让子元素保持自然高度、由容器滚动；
`.chat-page` 自身 `flex:1` 覆盖（同特异性、文件里更靠后），问答页保持不变。

**踩坑**：无头 chromium（ms-playwright 那个包）突然全线崩溃——
`Failed to create shared context for virtualization`，`--dump-dom` 空输出，

   改 `SELECT entity_id FROM (SELECT entity_id, MIN(depth) d FROM nb GROUP BY 1) t ORDER BY d, entity_id`

2. **实体搜索 500**：`func.cast(Entity.aliases, text("text")).ilike()` →
