**已确定的关键技术决策（后续实现须遵守）**
1. 用户给的 Milvus `a0fb1431…8704e` 是 **Token 不是 URI**（纯十六进制、无 scheme/host）。配置必须拆 `MILVUS_URI` + `MILVUS_TOKEN`，加载层做格式兜底 + 启动自检。

4. Embedding 用 **BGE-M3**（1024 dense + 稀疏权重），一次前向产出双向量；rerank 用 `bge-reranker-v2-m3`。
5. 切块策略：**父子分层**（parent 1400 / child 400 / overlap 60）+ 章节摘要（level=3），small-to-big 检索。
6. Milvus 单 collection 多书共存，`novel_id` 作 **partition key**；`chunk_id = {novel_id}:{chapter_no}:{seq}`。
7. Neo4j 关系统一用 `RELATED_TO {relation}` 属性而非独立关系类型（便于题材扩展）。
8. 架构形态：**模块化单体 + 独立 Celery worker**（ingest / graph 分开），二期按 §10.2 触发条件拆服务。
9. 检索：dense+sparse 并行 → RRF(k=60) → rerank top8 → 回溯 parent；降级链 hybrid→dense→sparse→摘要兜底。
10. 存储抽象 `ObjectStorage` Protocol（Local/S3），DB 只存 key 不存路径，迁移零代码改动。

**实测数据（写进 README 与架构说明书，替换了原先估算）**
| 场景 | 结果 |
|---|---|
| 38,485 字 / 24 章 | 144 子块 + 48 父块，覆盖度 99.71%，10.4s |
| 1,127,180 字 / 620 章 | 4,279 块，638.8s（10.6 min），写入 4279 = 存储 4279 |
| Embedding 吞吐（4 线程 FP32 ONNX） | 100 字 72 块/s、300 字 8.8、400 字 5.7 → 全程均值 6.7 块/s |
| GBK 文件 | charset-normalizer 判定 `gb18030`，正文无乱码 |
| 重跑幂等 | 同书重跑仍 144 条，Milvus 总数 288 = 2×144，无重复 |

**踩到并修掉的坑（重要，后续别重犯）**
1. **Milvus 一致性**：Zilliz Serverless 默认 Bounded，刚 insert 完 `count(*)` 读到旧快照（144 读成 128）。→ `MILVUS_CONSISTENCY=Strong`，已加进配置与 `.env`。
2. **glm-5 是推理模型**：一句话问答也要 208 reasoning token，`max_tokens` 给小会返回**空 content**（finish_reason=length）。→ 问答 3000 / 抽取 4000，并保留 `probe()` 探测 json_mode。
3. **HuggingFace Xet CAS 401**：hf-mirror + huggingface_hub 拉 LFS 会卡死/401。→ 弃用 fastembed，自写 `OnnxEmbedder`，模型文件从 ModelScope 拉（`Qdrant/bge-small-zh-v1.5`，94MB），首次自动补齐、之后离线。
4. **BGE 池化是 CLS 不是 mean**，归一化后直接 COSINE。
5. **uv pip install 会因网络卡住**（onnx 装了一半留下空目录，导致 `import onnx` 成功但 `_mapping` 报错）→ 已删残留目录。要用 onnx 量化必须走 `uv add` 而非 `uv pip install`。

**刻意保留的降级路径**
- `EMBEDDING_PROVIDER=hash` + `VECTOR_BACKEND=numpy`：模型/网络异常时链路仍可跑通，`/health` 标 degraded，不静默失败。
- 任务队列 `workers/runner.py` 单队列串行（4 核并行只会互相抢线程），换 Celery 只改 `submit()`。
