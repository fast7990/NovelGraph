长篇小说 RAG 检索 + 知识图谱 双引擎

原始文本 → 向量库（Milvus 3.0）+ 知识图谱（Neo4j）→ 可视化中台 + 大模型增强问答。 写入异步可重跑，查询同步可降级，两个引擎共享同一套标识体系。

Milvus 3.0.x · 阿里杭州托管 Neo4j 5.x 大模型 360 网关 · z-ai/glm-5 Embedding 本地 · bge-small-zh / bge-m3 后端 FastAPI + Celery · uv 前端 React + G6 + ECharts · pnpm

① 连接参数需要拆分

你给的 a0fb1431…8704e 是纯十六进制串，没有 scheme/host，形态是 Token。必须补 MILVUS_URI（实例地址），Token 放 MILVUS_TOKEN。配置层做格式兜底 + 启动自检，避免上线才发现连不上。

② 3.0 改变了分工

服务端 BM25 + 新稀疏索引（体积约 2.6 版的 1/3）、SINDI 学习型稀疏、服务端 ORDER BY/聚合。混合检索可以少跑一个客户端编码器，统计面板可以下推引擎。

③ 大模型走 OpenAI 兼容网关

360 网关 api.360.cn/v1 + z-ai/glm-5，全部调用走 openai SDK 覆盖 base_url。换 DeepSeek 只改环境变量。不假设上游有 prompt 缓存，成本靠上下文预算控制。

④ 切片过程必须看得见

按字符数算真实进度，附 token 分布、8 类异常检测、抽样预览。每条告警可跳转原文核查——切片是最容易错、也最难核实的一步。

01 总体架构

四层结构：接入 → 应用 → 能力 → 存储。能力层左右分置"写入管道"与"查询链路"，二者只通过三份共享标识耦合，互不阻塞。

02 双链路数据流

左：上传后自动触发的构建管道，异步、可断点续跑、幂等。右：单次问答的检索增强链路，同步、低延迟、可逐级降级。

WRITE

构建管道（100 万字 ≈ 30 min）

  1. 上传与去重sha256 命中则直接返回已有 novel_id；文件落 raw/{novel_id}/
  2. 解析编码探测（GB18030 兜底）→ 目录剔除 → 章节正则 + 长度兜底 → 清洗
  3. 分层切块parent 1400 tokens / child 400 tokens（overlap 60），对话归属识别
  4. 章节摘要v4-flash 并发 8，产出 150 字样章摘要（同时入向量库 level=3）
  5. 双通道向量化本地 bge-small（CPU）出稠密向量，稀疏走 Milvus 服务端 BM25；有 GPU 换 bge-m3 一次出双向量
  6. 图谱抽取规则候选 → v4-pro JSON 抽取 → 别名对齐 → 置信度闸门
  7. 入库Milvus 批 500 upsert；Neo4j 单事务 1000 条 UNWIND MERGE
  8. 索引就绪create_index + load；状态置 READY，问答立即可用（图谱略滞后不阻塞）
READ

问答链路（P95 首字 < 2 s）

  1. Query 改写v4-flash 做指代消解 + 关键词/实体抽取 → standalone_query
  2. 并行召回Milvus hybrid（ef=64，filter novel_id + level==1，limit 50）
  3. 图谱并发实体定位 → 2-hop 子图（≤60 边）→ 三元组文本化（≤40 条）
  4. RRF 融合Σ 1/(60+rank)，对分值尺度不敏感，换模型不用调参
  5. 精排bge-reranker-v2-m3，top50 → top8（约 80 ms）
  6. 回溯父块child 命中 → 取 parent 原文，最多 4 个，控制在 8K token 内
  7. Prompt 组装固定前缀（字节稳定）+ 图谱事实 + 资料 + 历史，总预算 ≤ 8K
  8. 流式生成SSE 推 delta → citations → done；断连立即释放上游连接

03 切片完成度查看

进度按「已切字符 / 总字符」计算——块数在流式切分中事前未知，用它算会出现越跑越退的假进度。 块数、token 分布、异常告警是副指标，用来判断"切得对不对"，30 秒内就能看完。

04 三份存储的建模边界

Milvus 存向量、Neo4j 存关系、PG 存事实与状态。正文只放在 PG 与原文文件里——向量库与图谱都是「可重建的派生索引」。

Milvus 3.0 novel_chunks_v1

  • chunk_idPK · {novel}:{ch}:{seq}
  • novel_idpartition key
  • level1 child / 2 parent / 3 摘要
  • denseFLOAT_VECTOR 1024 · HNSW M32
  • sparseSPARSE_FLOAT_VECTOR · SINDI
  • chapter_noINVERTED 索引
  • speakers / entitiesARRAY 标量过滤

Neo4j 5.x 图模型

  • 节点Novel Chapter Character…
  • Faction / Location势力 · 地点
  • Item / Event / Concept物品 · 事件 · 设定
  • RELATED_TOrelation 属性扩展
  • APPEARS_IN人物→章节 热度
  • PARTICIPATES_IN人物→事件 角色
  • 约束(novel_id, name) 唯一

PostgreSQL 元数据与状态

  • novelsmanifest 版本标记
  • chapters字符偏移 · 摘要
  • chunks正文 + 父子关系
  • jobs / job_steps状态机 · 断点
  • chat_messages引用 · 耗时 · token
  • vector_projectionUMAP 预计算坐标

06 实施优先级与交付标准

六个阶段约 37 人日（1 后端 + 1 前端）。P0 先打通「能问」的闭环，P1 补质量与可视化，P2 做生产化。

P0 · MVP 闭环≈ 13 人日

上传一本书，能基于向量检索问到答案，全程不碰命令行。

  • 上传 / 去重 / 本地存储
  • 解析 + 分章 + 三层切块
  • 本地 bge-small 向量 + Milvus 写入
  • 切片完成度复核页
  • 纯向量 RAG + SSE 流式
  • 最小管理台（4 页）
验收：100 万字 < 30 min；重复跑实体数不变；切片页可见进度/告警/抽样；20 条问题相关性 ≥ 3.5/5。
P1 · 图谱与质量≈ 15 人日

知识图谱上线，检索从单通道升级为混合 + 精排，两个可视化页面可用。

  • LLM 抽取 + 别名对齐 + Neo4j
  • 混合检索 + RRF + rerank
  • 图谱可视化（G6，2 跳子图）
  • 向量降维散点（UMAP 预计算）
  • 完整管理台四模块
验收：Recall@10 ≥ 0.85 且比纯向量基线高 8pt；200 节点子图渲染 < 1 s。
P2 · 生产化≈ 10 人日

从「能演示」到「能长期跑」：评测、审核、监控、切换对象存储。

  • 100 条评测集 + 回归脚本
  • 低置信实体人工审核队列
  • Grafana 看板 + 依赖健康降级
  • S3 适配器（MinIO 验证）
  • 压测 + 限流 + 成本看板
验收：make eval 一键出报表；20 QPS 压测零错误；切 S3 零代码改动。

07 主要风险与对策

风险影响对策
Token 当成 URI 用阻断补 MILVUS_URI；配置层检测无 scheme 即判定为 Token，启动 fail-fast 并打印明确提示
LLM 抽取编造关系高三道闸门：confidence≥0.6 + evidence 原文回查 + 关系枚举校验；低置信进人工队列
人物多称谓导致图谱碎裂高别名对齐（编辑距离 + 字符重叠 + 向量相似）+ LLM 仲裁；管理台提供实体合并
Milvus SDK 与 3.0 服务端错配中锁定 pymilvus 实测版本；启动做索引能力探测，SINDI 失败回退 SPARSE_INVERTED_INDEX
云端网络延迟 / 限流中批写 + 客户端限速 + 指数退避；检索超时 3 s 降级到缓存结果
章节切分错误（无章节号长文）中多级正则兜底 + 长度约束二次切；管理台支持手动修正章节边界
360 网关限流 / 超时高信号量 4 + 429 指数退避；抽取失败转规则抽取并标记 low_confidence；保留 DeepSeek 备份通道（改 base_url 即切）
大图渲染卡死低后端强制 limit，超 500 节点返回 truncated=true 并提示缩小范围
